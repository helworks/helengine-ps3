# Native authored RSX program and texture owners

`Ps3AuthoredProgram` and `Ps3AuthoredTexture` are standalone native PS3 owners for a validated cooked shader pair and explicit RGBA storage. They consume `Ps3ShaderArtifactReader::Read`, then validate the complete CPU DTO with `Ps3RsxProgramValidator`; neither class provides a fallback program, interprets arbitrary authored constant-buffer bytes, or integrates Core/material/scene state.

## Program uploads

Call `Initialize` once with a live `Ps3Video` and a fully read/validated `Ps3CookedShaderProgram`. The owner keeps an immutable metadata/blob snapshot and aligned SDK stage copies; it copies fragment microcode to RSX memory and retains it for every queued program load. `Program()` throws before successful initialization and after retirement. Copy and copy assignment are disabled.

Each draw follows `BeginDraw`, uploads every active mapping, `FinishUniformUpdates`, then binds required textures and submits the draw. `BeginDraw` reloads both programs and resets per-draw completion, so an earlier draw's values cannot satisfy the next one. Uniform indices are those in `Program().Vertex.Uniforms` (stage `0`) or `Program().Pixel.Uniforms` (stage `1`). The uploader resolves each validated `GeneratedName` in the actual SDK constant table; authored register bindings are not physical RSX indices.

`UploadUniform` accepts finite SDK register vectors, not raw little-endian authored buffers. It requires exactly `SdkElementCount * lanesPerElement` values: float1/2/3/4 use one/two/three/four floats per element; matrix3x3 and matrix4x3 use three; matrix3x4 and matrix4x4 use four. Matrix and vector arrays are explicitly iterated one SDK record at a time, preserving each record's hardware index. The fixture supplies its asymmetric transform as four SDK dot-product vectors in the order pinned by the producer shader and SDK dump; renderer integration must independently interpret reflected authored layout rather than assume this API performs that conversion.

All stage/index/type/count/finiteness checks happen before parameter commands. Missing active values fail `FinishUniformUpdates`. Fragment writes use PSL1GHT's FIFO parameter API and finish with `rsxUpdateFragmentProgramLocation`, preserving ordered updates across consecutive draws without mutating submitted cooked bytes.

## Texture formats and resource lifetime

`InitializeRgba2D` accepts only non-null row-major RGBA8 with each dimension from one through 4096 and an exact, overflow-checked byte count. It explicitly packs each texel to the SDK A8R8G8B8 channel word, owns a 128-byte-aligned linear RSX allocation, and configures normalized 2D sampling, one mip level, explicit identity remap, nearest filtering, clamp-to-edge and no gamma conversion.

`InitializeSolidCube` is an explicit constant-color resource, not an implicit substitute for missing authored texture data. It writes the caller's RGBA color into all six swizzled 1x1 faces at 128-byte face strides, using a 128-byte-aligned allocation. It makes no face-orientation claim. `Bind` accepts only the actual mapped RSX unit 0–15 and submits cache invalidation plus the complete sampling state; invalid calls report an error before issuing commands.

`Ps3Video` is borrowed by each initialized owner and must outlive every owner API call. After successful `Ps3Video::Drain`, call each owner's `ShutdownAfterDrain` while that video object is still alive; this is the normal retirement path and must reduce `OwnedGpuBytes()` to zero. Destructors are deliberately independent of the borrowed pointer: if an owner is still initialized, they log `missing-explicit-ShutdownAfterDrain` and `retainedGpuBytes`, retain RSX allocations through process exit, and never infer GPU safety from a possibly dangling video pointer. The caller must therefore explicitly shut owners down before destroying `Ps3Video`; destruction without that step is a reported lifecycle violation, not a fallback cleanup path.

## Pixel gate and scope

`tests/native/Ps3AuthoredGpuTests.cpp` loads the real P3SP and exact raw blobs generated by `Ps3ShaderGpuFixtureTests`. It renders the indexed position3/UV2 quad with the reflected hardware slots and sampler unit, checks four distinct 2x2 nearest-sampled colors plus the clear background, then repeats the draw using different vertex and pixel tints. All ten screen samples are reported with expected/actual RGB; per-channel tolerance is two. Readback occurs only after the associated present is waited by `Ps3Video::BeginFrame`.

Run the producer first with `HELENGINE_PS3_REPOSITORY_ROOT` set to this checkout and `HELENGINE_PS3_SHADER_GPU_FIXTURE_ROOT` set to a fully qualified directory strictly below `C:/dev/helworks/builds/helengine-ps3/shader-integration-20260923/authored-gpu`. Then run `scripts/tests/ps3-authored-gpu.tests.ps1` with that fixture root and an output-root descendant of the same task directory. The runner verifies the pinned image, hashes all relevant inputs, compiles only in network-disabled locked Docker, creates a schema-1 launcher manifest from actual outputs, invokes the existing visible RPCS3 launcher, and requires fresh named assertions and exact pixel records from that run's TTY log.

This is a reusable GPU path gate, not Core/material integration, not `cube_test` acceptance, and not physical PS3 hardware validation. Emulator pixel readback must not be generalized into a hardware-support claim.
