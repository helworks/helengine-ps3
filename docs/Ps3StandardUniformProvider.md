# PS3 standard uniform provider

`helengine::ps3::Ps3StandardDrawData` is the caller-owned per-draw input for the authored `ForwardStandard` shader. `Ps3StandardUniformProvider::Resolve` maps one validated `Ps3CookedShaderUniform` at a time to the SDK-ready float sequence consumed by the program upload path. The provider is CPU-only: it does not load materials, allocate GPU resources, cache programs, or change renderer behavior.

The world, world-view-projection, and normal matrices supplied through the draw DTO are already packed as four SDK dot-product vectors. The resolver copies all sixteen values in order. It does not transpose based on the reflected `RowMajor` flag. The per-light shadow matrices are emitted as identity values by the no-shadow policy. The asymmetric matrix convention was measured separately on GPU; the standalone provider test checks copied float order against distinctive inputs.

All caller-provided camera, base-color, ambient, and directional-light values are explicit float4s. Required values must be finite. A lit draw uses its supplied ambient radiance and, when `HasDirectionalLight` is true, one directional-light slot. That slot uses directional type `0`, the supplied RGB color, and the supplied XYZ direction without negating it; the shader performs its own directional convention. A lit draw without a directional light retains its ambient input and sets the active-light count to zero. An unlit draw uses white ambient and zero active lights.

The provider has an explicit no-shadow policy. Shadow metadata, atlas rectangles, and per-light metadata are zero; each `WorldToShadowClip` value is identity. `materialFlags` is zero, so this mapping does not enable shadow reception or emissive-texture selection. Surface policy values are roughness `0.4`, metallic `0`, specular `0.5`, and emissive color zero. Double-sided state remains available on the draw DTO for raster-state handling and is not exposed as a shader uniform.

Only exact buffer/member names from the supported standard shader are accepted. Resolution rejects unknown names, incorrect bindings, scalar labels, vector or matrix dimensions, array lengths, SDK types or element counts, insufficient byte sizes, null destinations, insufficient capacity, and non-finite values required by the selected mapping. It resets `written` on entry, prepares output in local storage, and copies to the destination only after every check succeeds. Failures include buffer/member context and leave the destination floats unchanged.

The PPU regression target reads the immutable cooked `ForwardStandard` pair through `Ps3ShaderArtifactReader` and checks every active uniform in both stages. It prints each reflected buffer/member, binding, scalar and shape metadata, SDK type, and element count for coverage attribution. This validates CPU mapping against the artifact; it does not establish authored-scene rendering, texture sampling, lighting integration, or renderer/cache lifetime behavior.

Builds use the pinned Docker SDK image through `scripts/tests/ps3-standard-uniforms.tests.ps1`. Use `-BuildOnly` for compilation without launching RPCS3. Runtime acceptance must use the existing launcher after the parent grants the serialized emulator slot.
